# Lino OS 五层架构设计

> 版本：0.1（Phase 0 定稿，随实现持续演进）
> 原则：可靠、安全、自由、免费、美观。

## 战略定位（最高指南）

**第一版只做 PC 系统**；Server 是第二方向，先放一放——等 PC 站稳脚跟、把第一版发出去再说。
不碰 Phone、不碰 IoT。

- **核心问题 1 — Windows 太臃肿、老崩溃**：用轻量、稳定、可维护的 Linux 底子 + 自研精致界面替代。
- **核心问题 2 — Linux 装软件 / 适配太难，厂商不愿适配**：用统一安装器 + 完善生态反过来吸引厂商。
- **两个解法（互为因果）**：**软件好开发**（统一格式、跨发行版、跨架构，一次打包处处可装）
  加上 **生态完善**（用户多 → 厂商愿适配 → 用户更多，形成正循环）。
- **方向参照**：Android 本身就是一个 Linux 发行版，Lino 向它「生态规模 + 开发友好」的方向靠拢，
  但 Lino 只做 **PC**（Server 预留，择机再进）。

> 本战略是 Lino 一切技术决策的最高指南：任何取舍都服务于「软件易开发、生态全、占住 PC」。
> Server 与云原生的相关设计（如网络/存储/虚拟化的服务器级完备性）作为第二方向预留，不阻塞第一版。

## 0. 总览

Lino OS 采用「**从用户界面到硬件抽象**」的五层结构，自高到底：

```
┌─────────────────────────────────────────────┐
│ 1. 用户显示层   Lino Shell（桌面 / 窗口 / 动效）   │  ← 用户唯一的入口
├─────────────────────────────────────────────┤
│ 2. 用户应用层   VLC · App Installer · 虚拟机      │
├─────────────────────────────────────────────┤
│ 3. 安全层       沙箱 · 权限 · 进程隔离            │
├─────────────────────────────────────────────┤
│ 4. Linux 内核层  Linux Kernel                  │
├─────────────────────────────────────────────┤
│ 5. 硬件抽象·安全隔离层 类 Qubes · Secure Boot · UEFI │  ← 紧贴硬件（仅 UEFI 启动）
└─────────────────────────────────────────────┘
```

设计目标：**让任何普通用户不必面对终端、不必理解依赖，即可安全地安装和使用软件。**

- **两套安全层夹住内核**：第 3 层（内核之上）+ 第 5 层（硬件之上，即「硬件抽象·安全隔离层」）
  把第 4 层内核包裹在中间，形成纵深防御——应对「银狐木马」等病毒对操作系统的攻击。
- **应用二分**：**系统应用**（出厂自带、受信任签名）与**用户应用**（运行在用户态、通过递数据
  给内核处理）；二者要运行或处理数据，都必须先过第 3 层安全审查。

## 1. 用户显示层（Lino Shell）

- **职责**：桌面、窗口管理、Dock、系统托盘、开机动画、动效；是用户对 Lino 的全部感知。
- **原则**：可靠、安全、自由、免费、**美观**（精致动画是 Lino 的竞争力）。
- **技术路线（待定稿三选一，倾向保留前端优势的最优解）**：
  - Web 技术（HTML/CSS/JS + 轻量渲染层）——出效果最快；
  - Rust + 自绘（参考 System76 COSMIC）——性能与安全最佳；
  - Qt/QML —— 生态成熟。
- **现状**：`shell/index.html` 为该层高保真交互原型，用于先锁定视觉与交互。

## 2. 用户应用层

| 应用 | 职责 | 开源基础 |
|------|------|----------|
| Lino VLC | 自有音/视频播放器 | VLC（GPL-2.0+） |
| Lino App Installer | 统一应用安装/卸载/更新（**灵魂**） | 自研 + Flatpak |
| Android 虚拟机 | 运行 Android 应用 | Waydroid |
| Windows 虚拟机（可选） | 运行 Windows 应用 | QEMU/KVM |

## 3. 安全层

本层是内核之上的第一道安全闸，与第 5 层（硬件之上）共同把内核夹在中间（纵深防御）。

- **应用二分**：应用分为两类——**系统应用**（出厂自带、受信任签名、运行在独立高权限隔离域）
  与**用户应用**（运行在用户态，通过递数据给内核处理）；二者要运行或处理数据，都必须先过本层。
- **审查闸门**：运行前/安装前对应用与数据做威胁情报 + 病毒库查验（以开源 ClamAV 病毒库为主，
  可选接入第三方威胁情报），命中病毒即拦截，未命中方放行（无完美方案，规则持续更新）。
  **已落地**：`security/threatscan/`（ThreatScan 威胁扫描器，哈希签名匹配 + EICAR 自检）是审查闸门的
  首个可运行实现，已接入 Lino App Installer 的安装前扫描钩子（fail-closed：命中即拦截安装）。
- **应用沙箱**：与 Lino App Installer 的包运行格式绑定（复用 Flatpak 的 bubblewrap 沙箱）。
- **权限模型**：安装/首次运行时的显式授权，拒绝静默提权。
- **进程隔离**：最小权限、按需授权；向第 5 层的更强隔离（类 Qubes 隔离域）演进。
- **账户模型**：非管理员（标准）账户**不强制设置密码**（类似 Windows），支持免密登录 /
  开机自动登录，追求「开机即用」的体验；管理员账户及任何提权/系统更改操作仍需凭据授权，
  避免安全层被架空。

### 安全中心

- **形态（已定稿）**：**内核极简锚点 + 独立隔离域**——内核里只保留一个反篡改的极小 watchdog，
  安全中心主体作为最高特权、独立于普通用户态的隔离域运行：用户态全部崩溃时它仍存活，
  同时避免把大段代码塞进内核，出 bug 不会带崩整机。
- **职责**：病毒/威胁扫描、违规拦截、系统完整性自检、安全状态可视化（对接显示层的安全中心界面）。

> 关键协同：这层与「统一安装格式」是一体的——正因为安装格式统一且默认沙箱，
> 用户才能「放心双击安装」，这是「统一安装器」之所以是灵魂的内因。

## 4. Linux 内核层

- 直接采用主线 Linux 内核（GPL-2.0），开启与安全相关的 LSM（如 AppArmor / Landlock）。
- 内核与 Lino 用户态程序为两个独立程序，许可互不冲突。
- 目标支持 **x86_64 与 arm64** 双 CPU 架构，并集成三厂 GPU 内核模块（详见「硬件兼容矩阵」）。

## 5. 硬件抽象·安全隔离层（类 Qubes）

- **职责**：一套安全机制——通过硬件抽象把程序放进沙盒，所有数据处理都先经抽象、再运行，
  从底层保证硬件安全；与第 3 层共同把内核夹在中间（纵深防御，参考 Qubes OS 的隔离思路）。
- **组成**：
  - 硬件抽象 / 隔离层（hypervisor 或轻量虚拟机监视器方案，底层实现待定稿）；
  - **Secure Boot** 信任链（从固件到内核到用户空间的可信引导）；
  - **UEFI**：**Lino OS 仅支持 UEFI 启动**，不提供 Legacy/BIOS 兼容。
- **演进策略**：Phase 1–3 先让 Linux 直接引导（仍为仅 UEFI），Phase 4 再把本层
  作为隔离底座补到内核之下——保证每一步都有可运行产物。

## 6. 硬件适配矩阵（整机）

硬件适配是「装上就能用」的前提。Lino OS 的目标**不止是 CPU 与 GPU，而是适配电脑里的
一切硬件**——从核心芯片到每一类外设与每一种传统 I/O 接口，出厂即插即用。

### CPU

| 架构 | 优先级 | 说明 |
|------|--------|------|
| x86_64 | P0 | 覆盖绝大多数桌面/笔记本，先落地并保证完整支持 |
| arm64 | P1 | 覆盖 ARM 设备，内核与用户态需交叉编译 |

- Linux 内核原生支持两种架构；Lino 用户态程序（Shell、App Installer）须保证可移植。
- Flatpak 运行时支持多架构，统一安装器可跨架构分发，无需为每种架构各造一套。

### GPU

| 厂商 | 首选开源驱动路线 | 状态 |
|------|----------------|------|
| Intel | i915 / Xe + Mesa | 开箱即用，最省心 |
| AMD | amdgpu + Mesa（RADV / RadeonSI） | 开箱即用，省心 |
| NVIDIA | 保证现有 Linux 驱动完美运行 | 不作为重点，随社区影响力由厂商适配 |

- **NVIDIA 取舍**：不作为重点。只需保证现有支持 Linux 的驱动（开源 nouveau / NVK 与官方专有
  驱动）能正常、完美运行即可；待社区影响力足够大，厂商自会来做适配。
- 显示层经 Mesa（Vulkan/GL）渲染，三厂统一到 Vulkan 抽象，避免为每家 GPU 各写后端。

### 整机硬件（其余外设与 I/O 接口）

CPU/GPU 只是起点，Lino 覆盖整机。核心策略：**优先复用 Linux 内核现有驱动与固件，保证
「完美运行」，不重复造轮子**；待社区影响力足够，硬件厂商自然来适配。

| 类别 | 覆盖内容 | 技术路线 |
|------|---------|----------|
| 存储 | SATA / NVMe / eMMC / UFS / 光驱 | 内核 block 层 + NVMe/SATA 驱动，支持 TRIM 与 SMART |
| USB / 雷电 | USB 2/3/4、Thunderbolt、扩展坞 | 内核 USB 栈 + 雷电域驱动，即插即用 |
| 显示输出 | HDMI / DP / Type-C / VGA | DRM/KMS + 三厂 GPU，多屏与 HiDPI 交给显示层 |
| 网络 | 有线（e1000/r8169 等）、Wi-Fi、蓝牙 | 内核网络栈 + iwlwifi/ath + BlueZ，支持 WPA3 |
| 音频 | 板载/独立声卡、麦克风、扬声器 | ALSA + PipeWire，低延迟统一音频总线 |
| 输入设备 | 键鼠、触摸板、触摸屏、手写笔、手柄 | HID / libinput |
| 传统 I/O | **串口（COM）/ 并口（LPT）**、读卡器、扫描枪 | 内核 serial/parport 驱动 + 对应子系统 |
| 打印 | 打印机 / 一体机 | CUPS + IPP Everywhere + 厂商 PPD，免驱动打印 |
| 摄像头 | 内置 / 外接摄像头 | V4L2 + PipeWire，供视频会议与虚拟机使用 |
| 电源与传感器 | ACPI、电池、温控、风扇、亮度、加速度计 | 内核 ACPI + IIO/hwmon，休眠唤醒 |
| 虚拟化 | VT-x / AMD-V、VT-d / IOMMU | KVM + IOMMU，Android/Windows 虚拟机依赖 |

- **对 PC（第一版主攻）**：串口/并口等传统 I/O 覆盖，让 POS、工业、外接专业设备也能「装上即用」；
- **对 Server（第二方向，预留）**：网络、存储、虚拟化三类的完备，是将来进军服务器市场的基础；
- 内核按目标设备集成对应驱动与固件（firmware），第 5 层硬件抽象负责屏蔽上述差异。

### 对各族的影响

- 第 5 层：硬件抽象需屏蔽 x86/ARM 与三厂 GPU 的差异；
- 第 4 层：内核按目标设备集成对应驱动与固件（firmware）；
- 第 1/2 层：VLC 硬解、虚拟机 GPU 直通/加速依赖上述驱动能力；
- Waydroid：arm64 下原生运行；x86_64 下需 ARM 转译层（如 ndk-translation）才能运行多数 Android 应用。

## 统一安装器技术路线（核心决策）

「跨发行版安装不通用」已被 Flatpak / AppImage 等开源方案解决。Lino 的策略是**站在巨人
肩膀上、不重复造轮子**：

1. **复用 Flatpak 作为后端运行时与沙箱**（合法、开源、社区成熟、跨发行版）；
2. **自研 Lino App Installer**：商店 UI + 一键安装/卸载/更新 + 权限确认，全程零终端；
3. 仅做「体验与统一性」的差异化，而非另起炉灶造一个注定碎片化的新包格式。

这样既兑现「任意发行版通用 + 双击即装 + 免终端」，又不违反「合法、开源、可公开」。

## 阶段路线图

| 阶段 | 目标 | 可运行产物 |
|------|------|-----------|
| Phase 0 | 架构定稿 + 显示层原型 | `shell/index.html` |
| Phase 1 | 可启动/可安装 ISO（live-build + Calamares 引导安装） | 可刻盘安装的 `.iso` |
| Phase 2 | App Installer（后端 + 沙箱 + 商店） | 统一安装闭环 |
| Phase 3 | Waydroid / QEMU-KVM 集成 | Android/Windows 应用可跑 |
| Phase 4 | 类 Qubes 底层 + Secure Boot 强化 | 完整五层安全底座 |

> 术语区分：**Calamares** 是「把 Lino OS 装到电脑上」的系统安装器（Windows 安装向导的对位物）；
> **Lino App Installer** 是「装好之后、在系统里装软件」的应用安装器（本仓库 `apps/installer/`）。
> 两者不同层，别混淆。
